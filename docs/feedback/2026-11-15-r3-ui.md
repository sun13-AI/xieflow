## 三 · 专项核查：06 与 10 字节级相同（U1-1 证据链）

- `06-schedule-live.png` 与 `10-schedule-moved.png`：SHA256 前 16 位同为 `08C299C02B7C6AFD`，同为 51,985 字节，拍摄时间 12:55:45 / 12:55:50——**同一张图被作为两个状态提交**。其余 8 张哈希互不相同，时间戳 12:55:35–12:55:50 连续同批。
- 矛盾一（证据失真）：10 的索引称「第二条 seed 待办经 due-date 路由改到 2026-11-18 → 日程出现在 18 日格」，改期前后应至少存在一个可区分的像素差；与 06 完全同字节意味着「改期」动作在两图之间没有留下任何视觉轨迹，改期同步的真实证据为零。
- 矛盾二（06 自身叙事冲突）：06 索引称流程仅「seed 待办→设今天→日程落今天格」，但画面上 18 日格已有一块带「进行中」徽标的日程——按叙事此刻 18 日不应有块。要么 seed 描述不完整，要么 06 实际拍的是改期后的状态。
- 定性：任务单 6 必拍态中「待办改期→日程同步后」实际**零真实证据**——与 r2「tab 激活零证据」同级的形态缺失类 U1。方向一联动（待办改期→日程变）的 UI 证据链在本轮矩阵中断。
- 疑因指向（不读代码，仅按现象与 r3 README 自述的「连拍偶发无产出/按文件存在性守卫」推断）：shot.ps1 的 06→10 链路在两拍之间未真正执行改期动作或未重新截图。返工以「两图像素可区分」为验收线。

## 四 · 风格漂移检测（vs r1/r2）

- 页头字标、三药丸 tab（r2 两药丸的自然延伸）、右侧圆角轮次徽章（r3·日程与待办联动）、浅灰底 + 白圆角卡、蓝主色（激活药丸/主按钮/时间数字）、页脚小字规则行（r2「流转规则」→ r3「联动规则」）——全部延续，**无漂移**。
