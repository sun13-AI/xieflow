## 六、自曝（遗留问题，不阻塞收尾）

1. **物资库存 `location` 由 in/transfer 的 `to` 覆盖，custodian 不随转移变**：schema v13 `asset_transactions` 只有 `from`/`to` 两个位置字段、无 `to_custodian`；转移只换存放位置、保管人需经 `PATCH /api/assets/:id` 单独改。任务单未要求转移同时换保管人，如实记账。
2. **单位任务树 UI 无折叠/拖拽，流转按钮列全量四态**：用户可见所有目标态按钮，非法流转由 shared 守卫 + HTTP 400 兜底（见截图 05/06），按钮未做「合法子集」过滤（与审批页 `availableApprovalActions` 的精细口径不同）——低成本取舍，浏览器端点错会得到 inline 错误提示（audit 已锁 400）。
3. **单位任务建树层级只按 `parent_id`，无环路 UI 提示**：`buildTaskTree` 环路抛错由 api 400 返回，但用户在表单里填互相引用的父任务 id 时只会看到 inline 错误；任务单未要求交互式环路提示。
4. **物资删除 `ON DELETE CASCADE` 流水全删**：审计语义上流水是台账凭证，生产系统一般软删或保留流水；本轮按任务单「CRUD」字面实现硬删，e2e/audit 均有级联归零断言锁定。
5. **错误态为内联文案而非全屏错误页**：r16 错误态有「连接失败」标题 + 重试按钮；r17 物资错误态为左栏语义化文案（无重试按钮），与 r5~r15 部分页面同构，语义诚实但交互层级略低。
6. **十四药丸在 488px 下靠 7px/2px 收窄单行全显**：可读性偏小，<440px 未逐档实测（与 r16 8px/3px 同款未验项）。
7. **无 pwsh 7 / 三平台 CI 实跑**：shot.ps1 新增段全 ASCII、PS5.1 Parser 0 错误，unix 分支未实测（与 r5~r16 同款未验项）；属 lead 发版环节。
8. **`docs/plan.md` 记账未改**：路线图记账 / 版本 / tag / push / Release 属 lead 收尾职责（宪法第二条 + 第五条危险区），本轮严格未触碰。
9. **seed id 不连续**：shot.ps1 每轮 seed 后 DELETE，`AUTOINCREMENT` 不回退；截图记录 seed 物资 #1 / 任务 #1·#2，CDP 全链路新建 #2/#3/#4，均是真数据。
