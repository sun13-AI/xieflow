## 六、自曝（遗留问题，不阻塞收尾）

1. **身份模拟是前端输入，不是真实鉴权**：当前身份为可编辑文本框（方便 waizhuan 走多角色），api 的 `actor` 完全由调用方声明；M9 网络版接真实登录前，任何客户端都能伪造身份。任务单未要求鉴权，已在 UI 明示「当前身份」。
2. **步骤时间线显示的是「当前审批状态」而非每步完成时状态**：`approval_steps` 只存 action/assignee/comment/acted_at，没有动作后状态快照；通过态图中前两步也显示「已通过」。若要逐步还原状态，需要给 steps 加 `status_after` 字段（v13 迁移，超本轮范围）。
3. **delegate 不生成新的待审批步骤给接手人**：转交步骤记新 assignee，但接手人的「待办」来自 approvals.current_assignee 查询而非步骤表；语义正确，但若要做「转交通知」需要另加消息通道。
4. **审批类型只有四类白名单**：leave/expense/purchase/other 来自任务单示例；真实 OA 的类型树与表单字段（请假天数/金额/附件）未做，M8 第 2 片可扩。
5. **抄送人只存字符串、无用户表校验**：`approval_cc.cc_user` 有 UNIQUE 与非空守卫，但不校验用户存在性（单用户阶段无用户表）。
6. **审批删除不限状态**：`deleteApproval` 是 CRUD 而非状态流转，终态单也可删（audit 清理依赖此行为）；若要求「已结单不可删」需新增 shared 守卫，本轮未做。
7. **窄屏药丸 8px**：488px 下十二药丸全部可见靠进一步收窄字号/内边距（r12 原生 10px/6px → r16 8px/3px），可读性尚可但偏小；<440px 未逐档实测。
8. **无 pwsh 7 / 三平台 CI 实跑**：shot.ps1 新增段全 ASCII、PS5.1 Parser 0 错误，unix 分支未实测（与 r5~r15 同款未验项）；属 lead 发版环节。
9. **`docs/plan.md` 记账未改**：路线图记账 / 版本 / tag / push / Release 属 lead 收尾职责（宪法第二条 + 第五条危险区），本轮严格未触碰。
10. **seed id 不连续**：shot.ps1 每轮 seed 后 DELETE，`AUTOINCREMENT` 不回退；最终截图索引记录 seed #5/#6，CDP 全链路新建 #7，均是真数据。
