## 四、「用户第一次用」全链路（headless CDP 真点，0 数据起步）

在 scratch local 库的 api（8787）+ web（5173）上，无头页 `isolatedContext=r25-first-use`：

1. HTTP 建登录用户、部门「CDP研发中心」、成员 CDP张三（关联该用户）与 CDP李四；
2. 浏览器注入 token（localStorage）→ 审批页「当前身份」自动变为 **CDP张三**（`/api/org/members/me` 真正解析）；
3. 点「＋ 新建审批」→ 输入标题 → 打开审批人选人弹窗 → **部门筛选选「CDP研发中心」** → 点 CDP李四（回填框「CDP李四」+「CDP李四（CDP研发中心）」徽标 + 手改语义提示）→「确认发起」得审批 #1；
4. 点「提交」→ 时间线第 1 步显示「提交·发起人 CDP张三 **[CDP张三（CDP研发中心）]**」；HTTP `GET /api/org/members/1/usage` → `actionCount=1 / total=2`；
5. 为 CDP李四建第二个登录用户并关联 → 切 token 重载 → 身份变 CDP李四 → 点「通过」→ 第 2 步显示「通过·操作人 CDP李四 **[CDP李四（CDP研发中心）]**」，终态「已通过」，操作区零出边；usage 成员 2 `actionCount=1 / total=2`；
6. **reload**（带 `approvalId=1`）→ HTTP 回查审批标题/已通过态、两步 `actorMemberId=1/2` 与徽标姓名、usage 均不丢；
7. DELETE 探针审批/两成员/部门/用户 → `depts=0 members=0`；`shot.ps1 down` 后五个端口 listen=0；scratch 目录删除。

说明：清理时先在删掉自己（admin）会话前删了 user#1，随后删 user#2 返回 401（会话已失效），user#2 只存在于被整体删除的 scratch 库中，未触碰仓库 `data/xieflow.db`。
