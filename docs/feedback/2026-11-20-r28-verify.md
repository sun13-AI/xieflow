## 二、打回项（可执行、可验证）

### P2-1 · 第一次用：下拉框显示已有会议室，预约却提交 `roomId:1` → 400「会议室不存在：1」

- **根因定位**：`apps/web/src/MeetingsPage.tsx:82-85`，无 `?roomId=` 时 `roomId` state 硬编码 `1`、`form.roomId` 硬编码 `"1"`；`load()`（L95-112）拉回会议室后只 `setRooms`，不把选中项纠正到真实存在的会议室。`<select value={form.roomId}>` 在没有 value=1 的 option 时浏览器显示**第一间**会议室，用户以为已选好，实际 POST 仍是 `roomId:1`。 yanfa 全链路用 scratch 库从 0 建室拿到 id=1，恰好掩盖此缺陷；只要库里曾有会议室被删（新室 id≠1）或用户不点左栏列表，第一次预约必失败。
- **复现步骤（我亲跑两次）**：① scratch 库删空后经 UI 新建会议室（得到 id=4）→ 填标题/组织者 → 直接点「预约」→ `POST /api/meetings` 请求体 `{"roomId":1,...}` / 响应 400 `会议室不存在：1`；② 打开 `?page=meetings&date=2027-03-13`（无 roomId），下拉框显示 `r28-WZ-UI-roomA`（id=4），填空闲 12:00–13:00 直接预约 → 同样 400。点左栏会议室按钮（URL 得到 `&roomId=4`）后才 201。
- **建议修法（不动测试口径）**：`load()` 内 `setRooms(roomData.rooms)` 后，若 `roomData.rooms.every(r => r.id !== roomId)`，取 `roomData.rooms.find(r => r.active)?.id ?? 0`，同时 `setRoomId(next)`、`setForm(f => ({ ...f, roomId: String(next) }))`、`syncUrl(date, String(next))`；`next===0`（无启用室）时只提示、不 POST。
- **验收断言（返工后必须新增并可复验）**：headless CDP 从 0 室起步 → UI 建室（id 可为任意非 1 值）→ **不点左栏**直接预约 → 201 且请求体 `roomId=<新室 id>`、URL 自动带 `roomId=<新室 id>`；再以无 `roomId` 深链 reload → 重复预约仍 201。
