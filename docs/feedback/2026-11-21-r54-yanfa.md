## 一、闸门实现（严格按 lead 方案）

- `apps/api/src/server.ts:403` 新增 `REMOTE_NON_ADMIN_PATHS = new Set(["/api/auth/me", "/api/auth/guard"])`：remote 下仅这两个认证探针允许非 admin 访问。
- `apps/api/src/server.ts` 的 `onRequest` hook 在会话解析成功后加统一闸门：

  ```ts
  if (
    serverMode === "remote" &&
    !ALWAYS_PROTECTED_PATHS.has(url) &&
    !REMOTE_NON_ADMIN_PATHS.has(url)
  ) {
    try {
      assertPermission(ctx.user.role, "user:manage");
    } catch (err) {
      return authErrorReply(err, reply);
    }
  }
  ```

- 语义边界：
  1. `PUBLIC_AUTH_PATHS`（health / settings / register / login / logout / mode）原样公开；`/api/auth/register` 仍由路由自身执行 r53 注册闸门，admin 建账号能力不变。
  2. `ALWAYS_PROTECTED_PATHS`（me / guard / users）原样放行 hook，其中 `/api/auth/users` 路由自带 `user:manage` 断言；`me`/`guard` 两个探针 user 在 remote 下实测 200。
  3. 其余所有 `/api/*` 业务路由（含 `feeds/key`、同步、组织、备份、表单等）remote 下一律 `user:manage`；非 admin → `ForbiddenError` → `authErrorReply` 回 403 `{"code":"FORBIDDEN"}`。
  4. `local` 模式分支逐字未改（`if (serverMode !== "remote" && !ALWAYS_PROTECTED_PATHS.has(url)) return;`），单机匿名语义零变化；r53 六项修复与各路由既有 admin 闸门原样保留，形成双层防线。
  5. 单工作区语义：**一个数据所有者 = admin**；未引入多租户、归属表或角色定义变更。
