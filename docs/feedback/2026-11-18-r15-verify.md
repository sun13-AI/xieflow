## 二、白板真实 HTTP 链路（隔离 api:8792 / 临时库，独立探针）

按用户顺序真发请求，逐项读回：

| 步 | 实测 |
|---|---|
| 前置 | `GET /api/health` 200 `schemaVersion=11`；`GET /api/whiteboards` = 0 张 |
| 建板 | `POST /api/whiteboards {title:"复验白板·季度规划"}` → 201 `id=1`，标题逐字读回 |
| 建便签 | `POST /:id/items {type:"note",x:80,y:80,content:"第一张便签：真实内容核对"}` → 201；x/y/type/content 逐字读回；第二张 (340,80) → 201 |
| 批量移动 | `POST /:id/items/move` 两条 → 200 `count=2`；`GET /items` 回读 note #1=(**120,300**)、#2=(**600,300**)（真落库，非临时态） |
| AI 建板 | `POST /:id/ai-create {theme:"季度复盘"}` → 201 `count=7`；7 张均 note、内容含「季度复盘」、彼此无重叠；`GET /items` 共 9 条（落库确认） |
| **布局核对** | **失败**：全画布 9 条中 2 组重叠 `[[6,1],[8,2]]`（AI note 与既有 note）；独立复现脚本另得 `OVERLAP_PAIRS=[{AI #15 (80,260), 既有 #11 (120,300)}]`，`AI_AMONG_SELF_OVERLAPS=[]` |
| 导出 | `GET /:id/export.md` → 200 `text/markdown; charset=utf-8`，H1=`# 复验白板·季度规划`，含真便签内容与主题，`content-disposition: attachment` + RFC5987 中文名 |
| 4xx | 越权 board_id 404、x/y 越界 400、越权 item id 404、批量移动越界 400；4xx 后 note #1 坐标仍 (120,300)（零半态） |
| 清理 | `DELETE /:id` → 200 `deleted=true`；列表回 0 张 |

**根因定位（供返工）**：`packages/db/src/index.ts:1898` 把 `existing` 与 `drafts` 一起交给 `collisionResolve`，但 `:1906–1916` 的写库循环只 INSERT 新草稿，**从未把 `resolved` 中既有条目的新 x/y UPDATE 回库**。当既有条目的 y 大于草稿行（如既有 (120,300)、草稿 (80,260)）时，避让算法把既有条目下移、草稿留在原位，库里既有条目没动 → 两者重叠。`collisionResolve` 本身无错（变异红相证明断言锁的是真规则）；`planAiWhiteboard` 的 7 张草稿彼此也不重叠。**这不是探针误差**：audit 的「r15 AI 建板布局不重叠」只枚举 `ai.json.items` 自己，漏掉了既有条目。
