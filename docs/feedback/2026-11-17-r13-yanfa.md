## 六、自曝（遗留问题，不阻塞收尾）

1. **mock 回答是模板化引用复述**：`buildRagAnswer` 把 top1 命中片段与来源拼成回答，不做语义归纳；接真实模型只需换 Planner 注入点，citations 口径不变。
2. **RAG 意图词表是确定性关键词**：未做语义意图分类；「查资料」类同义变体（如「帮我找找资料」）尚未覆盖，可在 shared `RAG_INTENT_KEYWORDS` / `extractRagQuery` 一处扩展。
3. **引用无额外鉴权**：`GET /api/knowledge/docs/:id?chunkId=` 只校验 chunk 归属文档，不做用户级权限（单用户阶段）。
4. **HTML/产物引用清单回退到消息**：四类产物的 JSON 正文都含 `citations`，但 `html-report` / `markdown-table` 的右侧清单实际回退到同轮 assistant 消息；两条数据源一致（均由同一 `exec.citations` 装配），但代码路径不同。
5. **引用卡跳转深链在 CDP 中 URL 先保留 `?page=knowledge&convId=`**（r12 P5-3 同款小 nit）：新建会话后 URL 未把 page 改成 chat，刷新会先回知识库 tab；数据不丢，重拍/真点均正常。
6. **窄屏引用卡为两列网格**：488px 下相关度与「查看原文」换行到下一行（06 图），未做更窄容器（<440px）逐档实测。
7. **本轮无 schema 迁移**：引用存 `content_json` 开放字段而非独立列，结构上更易读但不如专列可做 SQL 级聚合；若将来需要按引用反查会话，应走 user_version 迁移。
8. **本机无 pwsh 7**：shot.ps1 新增段全 ASCII（非 ASCII 字节 0、PS 5.1 `ParseFile` 0 错误），unix 分支未实测（与 r5~r12 同款未验项）；三平台 CI 未实跑（lead 发版环节）。
9. **e2e 在线口径**：1161 为服务离线口径；api 在线时 HTTP 冒烟节 +1 = 1162，README 已括注。
10. **未做发版动作 / 未改 plan.md 记账**：版本号 / tag / push / Release 资产核对与路线图记账属 lead 收尾（宪法第二条 + 第五条危险区），本轮严格未触碰。
