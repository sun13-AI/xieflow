## 七 · 问题分级

**U1（视觉坏功能 → 打回）：0 条。** 无乱码、无裁切、无塌陷、无形态缺失；任务单 6 态 + 加载 / 编辑 / 六 tab 壳矩阵完整；04↔01 差异真实；SHA256 全库亲算无新增同态组。

**U2（可用性别扭，记账不打回，3 条）**

1. **08 单元格编辑时整行「晃一下」：列宽跳变。** 2× 裁切对比 01 与 08 同位区域：01「状态」列表头约在 x≈168，08 因「名称」格内文本框把该列撑宽约 2.2 倍（输入框 ~225px），「状态」被推到 x≈318，其后**所有列整体右移约 150px**。用户点任一格进入编辑，整张表的列位会重排一次、退出再弹回；无裁切无塌陷，但连续编辑多格时视觉抖动明显，且不利于「按列位置形成肌肉记忆」。建议：编辑框用 `position:absolute` 覆盖原格 / 固定列宽 + 框内滚动，或至少让列宽在编辑态与非编辑态保持一致。
2. **筛选 / 排序控件缺提交反馈与无效控件。** 筛选值是自由文本框，提交时机为「失焦或回车」（仅 README 注记 2 说明），界面无「应用 / 清除」按钮、无「按回车生效」提示、无「正在筛选」态；用户输入后若不移开焦点，会以为没生效。另：「排序=（不排序）」时「升序 / 降序」方向下拉仍可交互但不起作用，属于可见却无效的控件。建议：加「应用 / 清除」按钮或回车提示，未选排序字段时禁用方向下拉。
