## 七、发现的问题（不打回，供 lead 收尾/排期）

- **P1（建议收尾前修，一行改动）** `scripts/shot.ps1:31`：`Start-Process cmd "/c pnpm dev:api > log 2>&1"` 未给 stdin 重定向，`tsx watch`（stdin 交互式 watcher）在无控制台的分离进程组里启动即退出——本人实测 2/2 复现：日志打印 `listening` 后进程消失、60s 超时 throw，而完全相同的生成方式下 vite（非交互）存活；用 `< NUL` 重定向 stdin 后同机实测 15s+ 存活（`port-up-after-15s: True`）。交互式终端里 `pwsh scripts/shot.ps1 all` 不受影响（lead 产出的 5 张图为证）。建议改为 `/c "pnpm dev:api < NUL > log 2>&1"` 或对 api 侧改用非 watch 启动。
- **P2（发版硬前置）** 无 git remote：宪法发版流程要求 push main + tag 由 CI 构建 Release，当前无法执行。需 lead 配置远端后 push，再 `pnpm version patch` → tag `v0.0.1` → 核对 Release 资产 → 记账。
- **P3（小）** ci.yml `on.push.branches: [main]` 与实际分支 `master` 不匹配（tag 触发不受影响）；建议统一，避免 push 不跑 CI。
- **P4（记录在案）** 断言两条自洽占位：「settings.value 非空约束生效」（e2e-test.ts:90-95，手动 throw 计数，未真触达 NOT NULL 约束）、「重开不重复执行迁移（幂等）」为恒真式。不影响总数合规（42 中 40 条为真实行为断言），建议 r2 起用直连连接句柄真验约束。
