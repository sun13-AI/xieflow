## 四、过程记录与坑（供后续轮次复用）

1. **TDD 红相留痕（r4 同款手法）**：`git stash push -- packages/shared/src/index.ts apps/api/src/server.ts`（只撤实现、保留断言）→
   - e2e 红：`SyntaxError: The requested module '@xieflow/shared' does not provide an export named 'BOARD_CSV_HEADERS'` → exit 1；
   - audit 红：`FAIL GET 看板统计 -> 200 (got 404, want 200)` + `FAIL 统计：projectId 回显` + `audit 抛错：Cannot read properties of undefined` → 断言通过 237 / 失败 3 → exit 1。
   `git stash pop` 恢复后两套全绿。断言不是自洽占位，路由不实现就跑不过。
2. **r4 教训 ①（HTTP 层必须测装配后行为）落实**：统计断言全部走 HTTP 读回（`GET /api/projects/:id/stats`），CSV 断言走**字节层**（BOM 三字节逐个断言）而非字符串前缀——因为 WHATWG fetch 的文本解码会把 BOM 剥掉（audit 里专门留了一条断言记录这个平台行为：`CSV：文本解码会剥掉 BOM（故 UI 必须按字节落盘）`）。**该行为直接决定了 UI 实现：导出必须 `arrayBuffer → Blob` 按字节落盘，按文本落盘会让 Excel 直开乱码。**
3. **TDD 红相抓到 2 处断言自身写错**（r4 教训 ②复现）：① 「物理行数 = 记录数 + 1」——错在字段内是裸 `\n`（不切记录），已改为正确口径并补「字段内 CRLF 会多出物理行」的对照断言；② audit 里用 `.slice(1)` 去 BOM——错在 fetch 解码后的文本本就没有 BOM，切掉的是真字符「列」，已改为 `stripBom()` 守卫式处理。**均为修正到正确口径，未放宽。**
4. **r5 新坑：headless 浏览器触发文件下载后不退出**（首轮拍图卡死在 03 号，进程 60312 挂住近 10 分钟）。处置：`shot.ps1` 的捕获改为「等 PNG 落盘（45s 上限）→ 5s 内不退出则 `taskkill /T` 杀浏览器树」，并**先删旧 PNG 再拍**（失败不得伪装成成功）。该改动对所有轮次生效（r1~r5 均受益），脚本仍 0 非 ASCII 字节 + Parser 0 错误。
5. **PowerShell 只准 ASCII 的新用法**：种子数据用 JSON `\uXXXX` 转义写中文（`"r5 \u7edf\u8ba1\u5bfc\u51fa\u9879\u76ee"`），服务端 JSON.parse 解回中文——既守住 ASCII 红线，又让截图/CSV 里有真实中文内容（r4 种子里是英文）。
6. **CSV 落盘用 `System.Net.WebClient.DownloadFile`**（原始字节）：`Invoke-WebRequest -OutFile` 在 PS 5.1 下可能按文本解码再编码，BOM 会丢——这正是「导出必须按字节」的同款坑。
7. **PowerShell 跨平台纪律保持**：shot.ps1 新增段全 ASCII；未用 `$isWindows`、未用 Windows 专属参数之外的写法；PS 5.1 Parser 实测 0 错误。
