**（1）三路径可理解性**：路径 A（cloud，已上线）→ 路径 B（docker-compose）→ 路径 C（portable）编号清晰，开头即给出「同一套部署契约 + `local`/`remote` 白话定义」，非技术用户能分辨「我不部署 / 机房部署 / 本机双击」三条路。C 路径的「双击 start.cmd → 浏览器 8080」与截图 02/04 完全一致，闭环。**需补强两处**：C 路径获取便携包的唯一写法是 `pnpm run pack`（或 `pnpm run dist` 产 zip），没有「从 GitHub Releases 下载现成 `xieflow-setup-<版本>.zip` 解压即用」的入口句，非技术用户若没有源码仓库与 Node 环境，第一步就走不下去（U2-3）；B 路径只给 `http://127.0.0.1:8080`，但自称「适合内网 / 客户机房」，机房其他机器访问需宿主 IP，文档未提示（U2-4 前半）。两处均不影响「照着做能在目标机上把服务起来」，不判 U1。
