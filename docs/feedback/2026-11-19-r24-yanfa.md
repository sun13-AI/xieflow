## 四、「用户第一次用」全链路（headless CDP 真点，0 数据起步）

在 scratch 库 local 模式的 api（8787）+ web（5173）上，用无头浏览器 CDP 真点：

1. `?page=org` 空态 → 「＋ 新建部门」建 **CDP研发中心** → 「＋ 新建人员」建 **CDP张三**（Frontend Engineer）与 **CDP李四**（Product Manager）；
2. 切「审批」→ 点申请人「从通讯录选人」→ 搜索结果点 CDP张三（输入框与 #1 徽标回填）→ 新建审批填标题、点审批人选人选 CDP李四 → 「确认发起」得审批 #1，发起人显示部门徽标；
3. 点「提交」→ 待审批、时间线 1 步；切身份选 CDP李四 → 点「转交」旁选人选中 CDP张三 → 点「转交」→ 当前审批人变 CDP张三、时间线 2 步且转交步骤带 member_id=1；
4. 切「物资」→ 新建物资填名称/库存/单位/位置 → 保管员选人点 CDP张三 → 「确认建账」得物资 #1，卡片与详情显示部门徽标 → 出入库入库 2 台、操作人选人点 CDP李四 → 「确认记账」得流水 #1，库存 5→7；
5. `GET /api/org/members/1/usage` → `{approvalCount:1, assignedApprovalCount:1, assetCount:1, total:3}`；成员 2 当时 total=0（转交目标为成员 1）；
6. **reload** → HTTP 回查审批 #1 与两步、物资 #1 与流水、部门 1 / 人员 2 全在；DELETE 探针 5×200 → 四类实体归零；端口收净，scratch 库删除。

说明：第 3 步提交时 UI 尚未把申请人 member_id 传给动作接口（提交步骤 member_id=NULL，转交步骤正确）。全链路后发现并把 `doAction` 的 `actorMemberId` 接到当前选人状态，源码已修正；audit/e2e 对动作 member_id 的断言原本就覆盖该字段，修正后复跑全绿。
