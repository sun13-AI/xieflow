     `✗ 队列超出 SCHEMA_VERSION：一致性校验抛错（未抛错）`，随后 `Error: 迁移队列最高版本 4 与 SCHEMA_VERSION 5 不一致` 退出 1。
   - audit 红（**本轮补做的滞后红相证明**）：`git stash push -- apps/api/src/server.ts`（只撤实现、保留断言）后跑批 →

     `FAIL CSV：文件名含项目名与日期（U2-2）` 等 **11 条失败**（新路由全 404 + 文件名口径未生效），
     断言通过 309 / 失败 11 → 非 0 退出；`git stash pop` 恢复后全绿。**断言不是自洽占位**：不实现路由就跑不过。
2. **r3 教训 ① 落实（HTTP 层必须测真实装配行为）**：字段类型的每一条口径都在 HTTP 层被真读回验证——

   `GET 记录?filterFieldId=<数字字段>&filterValue=abc` → 400（筛选值类型不符走的是真实查询串路径）；
   `GET 记录?sortFieldId=<数字字段>&sortDirection=desc` → 读回顺序 9000 / 1500 / 300（排序装配生效）。
3. **r4 教训（「用户第一次用」全链路）落实**：本轮多维表格**建表→加字段→加行→编辑单元格→筛选→排序**全链路用
   headless Edge + CDP **真点**跑通（见第五节），不是只验数据层。
4. **r5 教训（按字节落盘）沿用**：CSV 导出仍按字节落盘；本轮新增的**文件名**口径也统一在 shared，api 响应头与 UI 下载名同源，
   不会出现「头里一个名、落盘另一个名」。
5. **新坑①：外壳参数名撞车**——外壳用 `?page=` 选 tab，多维表格页若也用 `?page=` 做分页，浏览器 URL 的 `page=bases`

   **修法**：分页的浏览器参数改名 `pageNo`（api 侧仍是 `page`，两层参数名解耦）。**教训：外壳级参数与页面级参数必须分域。**
6. **新坑②：钉态与真实态同字节**——首轮把「一张表都没有」的钉态当 02 号空态图，结果与壳基线的 `bases-tab-active` **字节完全相同**
   （都是无表空态）。**修法**：02 号改为**真实空表**（表在场、零行、字段表头可见），
   「一张表都没有的首次使用引导」交给壳基线那张图——两张画面不同、哈希互异（`D458EB7D` vs `3675C103`）。
7. **PowerShell 纪律**：r6 种子数据全用 `\uXXXX` 转义写中文（`"r6 \u591a\u7ef4\u8868\u683c"`），
   字段 id 靠**默认模板的 position 顺序**取（0..7），脚本因此连中文字段名都不必出现——**纯 ASCII**（实测 0 个非 ASCII 字节 + Parser 0 错误）。

## 六、自曝（遗留问题，不阻塞收尾）

1. **筛选是「单值 + 单字段」语义**：只支持一个筛选字段 + 一个筛选值（多选字段按「包含」匹配）。
   多字段 AND 筛选、日期区间筛选未做——属 r7「视图与导入」轮的活，本轮任务单只要求「按字段筛选」。
2. **记录 data 以「字段 id 字符串」为键**（不是字段名）：好处是改字段名不会丢数据；代价是**直接读库文件**的人
   必须先查 `fields` 表才知道哪个键是哪个字段（README 与本报告已写明）。若 r7 要做 CSV 导出，列名需按字段表映射。
3. **删除字段会清掉该字段在所有记录里的键**（不留孤儿值）——这意味着**删字段即丢该列数据**，UI 未做二次确认提示。
   本轮沿用了 r4「删除即生效、错误消息稳定」的既有口径；若 waizhuan 认为需要确认弹窗，请列入返工清单。
4. **U2-1 的改名只改了 UI 文案，HTTP 层没有可断言字段**：看板统计接口返回的 `completionRate` 字段名未变（改它会破 r5 断言与导出格式）。
   本轮以 e2e 断言（命名规则）+ 截图目验双证据背书文案改名；若要求「接口字段也改名」，需 lead 定夺是否算破坏性变更。
5. **r5 目录的看板图仍是改名前形态**（图里写「完成率」、导出文件名带 id）：本轮**未重拍 r5 目录**——重拍会破坏 r5 的
   「03 反馈条 × 04 落盘 CSV 真值对真图」证据链（r5 ui-reviewer 专项裁决过）。已在根 README 的 r5 小节与
