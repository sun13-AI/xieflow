## 三、变异红相留痕（宪法第四条第 4 款，1 组）

**目标文件**：`packages/shared/src/index.ts`（按序重放唯一规则 `planOfflineReplay`）；改前/还原后 SHA256 = `856E9F4A98EE959B0E123B0E50820B3439B972B8191EFA97FE3B1EDE09A6FCDF`（175856 字节；备份 `%TEMP%\r20-yanfa-shared-backup.ts`，备份 SHA 同值）。

**变异点**：`if (a.createdAt !== b.createdAt) return a.createdAt < b.createdAt ? -1 : 1;` → `... ? 1 : -1; // MUTATION-PROBE r20 replay order reversed`（把按序重发改成倒序，等价于「先发的后重放」）。

| 阶段 | 实测 |
|---|---|
| 改坏后 e2e | `pnpm test` exit **1**；**1801 通过 / 2 红**：「r20 replay 按 createdAt 升序串行重发（变异红相目标）」（实际 `["late","early"]` ≠ 期望 `["early","late"]`）、「planOfflineReplay 返回副本不改入参」（排序翻转后首元素命中原 late） |
| 改坏后 audit | `node scripts/run-ps1.js scripts/audit-http.ps1` exit **1**；**1481 通过 / 3 红**：「首条结果是 createdAt 更早的 early」「次条结果是 late」「先 createdAt 的待办先落库（真实顺序）」（got `r20 offline B …` want `r20 offline A …`） |

## 六、自曝（遗留问题，不阻塞收尾）

1. **只有 TodosPage 对 202 离线语义做了「已入队」文案处理**：其它写页（日程/项目/表格/文档等）在离线时仍会按旧逻辑显示「新建/保存失败」类文案，但请求**确实已入队持久化**，顶栏全局提示会明确告知队列条数。统一各页 202 分支是低成本后续项（本轮任务单重点是队列与状态机制，未逐页铺开）。
2. **离线队列只在浏览器 localStorage**：换设备/清浏览器数据会丢未同步队列；服务端没有 per-device 队列持久化（r19 自曝第 5 条设备维度同源），本轮按任务单「localStorage 持久化」交付。
3. **SW 在测试环境按设计禁用**：`?no-sw=1` / `?shot=` / `?narrow=` / `navigator.webdriver` 任一命中即不注册；因此「真安装 PWA 后离线打开」的端到端验证未做（只验了 SW 资源策略结构 + 离线 fallback 页面在场），属 headless 环境限制。
4. **重放冲突后的 UI 未做逐条选边**：`OfflineStatus` 的「立即同步」遇 409 会保留冲突及其后条目并给红条提示，但没有像 r19 冲突弹窗那样的逐条处理入口；需人工处理服务端冲突后再点同步。
5. **`app.inject` 重放入口的鉴权只转发原请求 Authorization**：没做 per-item 权限二次判定（既有路由自己的权限守卫仍生效），公网部署时应结合 remote 模式固定与 HTTPS。
6. **移动底部导航为 14 tab 横向滚动 + 汉堡展开 2 列**：在 390px 下底栏需横向滑动才能到末尾 tab（符合触摸 44px 与不折行约束），未在真机 iOS/Android 上实测（CDP device metrics 模拟）。
7. **06 图拍摄方式与其它六张不同（CDP device metrics）**：已在截图索引与本报告诚实记账；shot.ps1 的 390px 钳位未改（避免影响其它轮次已验脚本）。
8. **无 schema 迁移**：复用既有 v15 两表（r19 同步），CI smoke 正则未动。
9. **三平台 CI / unix pwsh 7 分支未实跑**：shot.ps1 新增段全 ASCII、PS5.1 Parser 0 错误；本机 Windows 限制，属 lead 发版环节。
10. **`docs/plan.md` 记账未改**：路线图记账 / 版本 / tag / push / Release 属 lead 收尾职责（宪法第二、五条），本轮严格未触碰。
