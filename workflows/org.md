# 协流 XieFlow — 编制表（org.md）

> 基准流程 = IKanBot 双 agent 模式（研发 → 使用者实跑复验 → VERDICT → 打回返工 → 每轮发小版本）。
> 本表先固化基准模式，再以「并行观察、不阻断」的方式试扩展岗；扩展岗只有证明净增益后才升级为阻断岗。

## 一、基准流程（IKanBot 模式，先跑通）

```
项目总监（lead）拆任务单
   ↓
研发视角 yanfa：TDD 实现 + 截图矩阵 + 研发报告（本地提交，不 push）
   ↓
使用者视角 waizhuan：实跑复验，不读研发报告实现细节 → VERDICT: 通过 / 打回
   ↓
通过 → 项目总监收尾：pnpm version patch + tag + push + CI Release + 核对资产 + 记账
打回 → 研发视角返工（同轮号追加「返工 #k」）→ 重新复验
```

IKanBot 同款硬规则（已在 AGENTS.md 落地）：截图矩阵每轮无例外、每轮必发小版本、复验报告末行 VERDICT、报告三态纪律、每轮记账。

## 二、编制与汇报线

```
owner（人类，最终决策权）
└── 项目总监 director（lead 担任，项目内最高决策岗）
    ├── 研发视角 yanfa（实现岗）        ← 基准流程
    ├── 使用者视角 waizhuan（复验岗）   ← 基准流程
    └── UI 审查官 ui-reviewer（界面质量岗）← 扩展岗，r2 起并行观察、不阻断
```

| 岗位 | 正式名 | 提示词 | 履历 | 汇报对象 | 核心交付 | 当前状态 |
|---|---|---|---|---|---|---|
| 项目总监 | director | workflows/director-prompt.md | docs/staff/director.md | owner | 任务单、发版、裁决、履历维护 | 基准 |
| 研发视角 | yanfa | workflows/yanfa-prompt.md | docs/staff/yanfa.md | 项目总监 | 代码 + 断言 + 截图 + 研发报告 | 基准 |
| 使用者视角 | waizhuan | workflows/waizhuan-prompt.md | docs/staff/waizhuan.md | 项目总监 | 实跑记录 + VERDICT | 基准 |
| UI 审查官 | ui-reviewer | workflows/ui-reviewer-prompt.md | docs/staff/ui-reviewer.md | 项目总监 | 逐张验图记录 + UI-VERDICT | 扩展（观察中） |

## 三、扩展岗的升级门槛（先试，不急着要）

UI 审查官在 r2 以**并行观察员**身份运行：出 UI-VERDICT 报告，但**不阻断发版**（发版裁决仍以使用者视角的 VERDICT 为准）。
升级为阻断岗需满足：① 连续 2 轮观察中至少抓到 1 个使用者视角漏掉的真问题（U1 级）；② 不产生误报噪音；③ 每轮额外耗时 < 10 分钟。
达标则从 r3 起进入「双 VERDICT 并行裁决」（见下）。

```
项目总监：写任务单 → 拉起研发视角
    ↓
研发视角：TDD 实现 + 截图矩阵 + 研发报告
    ↓
使用者视角（实跑用户路径）  ┐ 并行（r2 起）
UI 审查官（逐张验图，观察中）┘
    ↓
r2：使用者视角 VERDICT 通过 → 发版（UI 意见记账）
r3+（达标后）：两份 VERDICT 都通过 → 发版
```

## 四、职责边界（防串供与职责重叠）

- 使用者视角**不读**研发报告的实现细节，只按任务单走用户路径
- UI 审查官**不评**代码与断言（那是使用者视角与断言纪律的事），只评：截图真实性、形态覆盖完整性、视觉一致性、可用性别扭点
- 研发视角不自评；发现自己实现的问题写进报告「自曝」节（诚实加分，隐瞒扣分）
- 三岗互相不沟通，全部通过仓库文件交换信息

## 五、岗位设置原则

- 一个岗位 = 一份独立视角；开新岗的前提是**现有岗位覆盖不到的质量维度**
- 暂不单设「测试工程师」：断言纪律由研发视角（TDD 义务）+ 使用者视角（规模核对）双覆盖，避免职责重叠
- 预留岗位（到里程碑再设）：评测官（M5 起，锁 AI 工具调用行为）、安全官（M9 起，远端模式）
- 每完成一个大里程碑，项目总监复审一次编制（宪法第六条同款）

## 六、履历维护规则

- 项目总监每轮收尾时更新 `docs/staff/<岗位>.md`：追加履历行、更新绩效纪要
- 履历只记事实（做了什么、发现什么、裁决什么），不写评语式表扬——绩效纪要用数字说话
- 员工换人（新会话）不影响履历连续性：履历跟岗位走，不跟会话走
